wheregoes-cli

A command-line tool that traces any URL through its full chain of HTTP redirects until it reaches its final destination. For every hop in the chain, it captures and displays the response metadata (status code, headers, timing) and response body, giving developers full visibility into where a link actually goes and what each server along the way returns.

Go Compiled single binary Distributed via go install

What the app does

  • Redirect chain tracing

    Follows every HTTP redirect from a starting URL until it lands on a final, non-redirecting response.

  • Per-hop inspection

    Shows status code, response headers, response body, and timing for every hop in the chain, not just the final page.

  • Colorized terminal output

    A clean, numbered, color-coded trace prints by default, with the final destination clearly highlighted.

  • Copy & clean final URL

    Copy the final destination URL to the clipboard, optionally stripping tracking parameters like utm_* tags first.

Out of scope (v1)

  • JSON / machine-readable output — scripting and piping support can come in a later version; v1 is terminal-only.
  • Batch mode — v1 traces one URL per invocation, not a list or file of URLs.
  • GUI / browser extension — this is a CLI-only tool.
  • JavaScript / meta-refresh redirects — v1 only follows HTTP-level 3xx redirects, not client-side JS redirects or <meta http-equiv="refresh"> tags, which require a real browser engine.
  • Shortener-vendor analytics APIs — generic HTTP redirect following already expands shortened URLs; v1 does not call vendor-specific APIs (e.g. Bitly) for extra click-analytics metadata.
  • History / logging of past traces — no persistent local database of previously-run traces.
  • Config file / saved profiles — v1 takes flags per invocation only, no persistent settings.

Data model

What the app needs to remember. There is no persistent storage — this is the in-memory shape built up during a single run and printed to the terminal.

Trace

final url where the chain ends up

Milestones

1

Core redirect tracer

A basic CLI that takes a URL, follows the full redirect chain, and prints each hop's details in plain text. This is the first fully working, testable version of the tool.

What gets built

  • Basic usage: wheregoes <url> takes a starting URL as a command argument
  • Follows every HTTP redirect (3xx with a Location header) automatically until a non-redirecting response is reached
  • A safety limit on the number of hops followed; a clear error is shown if exceeded instead of the tool hanging
  • Clear error message for a malformed or unreachable starting URL (e.g. DNS failure, connection refused)
  • For each hop: requested URL, status code, response headers, response body, and per-hop timing, printed as plain text
  • Very large response bodies are truncated in the display with an indicator that they were cut off
  • Total elapsed time for the whole chain shown at the end

Not in this milestone

  • Colorized or visually organized output (plain text only in this milestone)
  • Clipboard copy or tracking-tag stripping
  • Retrying failed requests automatically
  • Parsing or pretty-printing structured body content (JSON/HTML formatting)

Done when: Running wheregoes <url> against a URL with multiple redirects prints every hop with its status code, headers, body, and timing, ending with the correct final destination, and running it against an invalid URL shows a clear error instead of crashing or hanging.

2

Colorized output polish

Upgrades the plain-text output from milestone 1 into the full colorized, numbered, visually-organized trace display.

What gets built

  • Each hop is visually separated and numbered (e.g. "Hop 1", "Hop 2") so the chain reads top-to-bottom
  • Status codes are color-coded (e.g. green for success, yellow/orange for redirects, red for errors)
  • Headers and body are visually distinguished from each other via labels, spacing, or dimmed text
  • The final destination URL is visually highlighted/called out distinctly at the end of the trace
  • Output degrades gracefully to plain text when color isn't supported (e.g. piped to a file or a non-color terminal)

Not in this milestone

  • Interactive/scrollable terminal UI (TUI with panes or live updates)
  • Custom themes or user-configurable colors
  • Progress bars/spinners during the trace
  • Clipboard copy or tracking-tag stripping (milestone 3)

Done when: Running wheregoes <url> in a color-capable terminal shows a numbered, color-coded trace with a clearly highlighted final destination, and the same command piped to a file produces clean, readable plain text with no stray color codes.

3

Copy & clean final URL

Adds clipboard integration and tracking-parameter stripping for the final destination URL.

What gets built

  • A --copy flag that copies the final destination URL to the system clipboard after tracing completes
  • A --clean flag that strips common tracking/marketing query parameters (utm_source, utm_medium, fbclid, gclid, etc.) from the final URL
  • The two flags can be combined (copy the cleaned URL) or used independently (clean and print only, or copy as-is)
  • A confirmation message printed to the terminal when a URL was copied

Not in this milestone

  • Copying anything other than the final URL (no full trace or headers to clipboard)
  • A configurable/custom list of which tracking parameters to strip — v1 uses a fixed built-in list
  • Clipboard history or multiple clipboard formats

Done when: Running wheregoes <url> --copy --clean traces the chain, prints a confirmation, and pastes back the final destination URL with tracking parameters removed.
